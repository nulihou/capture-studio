# Capture Studio 产品规格

基线日期：2026-10-12。本文定义产品该做什么、怎样才算可入库，以及当前代码相对规格差在哪里。`README.md` 和按日期命名的诊断记录只作操作说明与证据，不覆盖本文。

## 1. 产品定义

Capture Studio 是 Windows 桌面采集工具。一次会话里，一台 USB 摄像头只接一台主机，主机在本地写下源视频。桌面程序负责选设备、看画面、开始和停止、把板端文件取回，并生成可复核的会话目录。

产品交付物是会话，不是模型标签，也不是推理结果。会话要能回答四件事：谁在什么场景采集、请求了什么参数、磁盘上的文件是否就是当时写下的文件、这些文件在声明的分辨率下能否逐帧解码。

目标用户是数据集采集员。板端维护只在首次安装或更换 KV260 时出现。

## 2. 范围

产品包含：

- 电脑直连 USB，在 Windows 上录制。
- KV260 直连 USB，在板端录制，停止后取回电脑。
- 录制前预览，用于对镜头和视场。
- 分段 Matroska、SHA-256、逐帧容器时间戳清单。
- 便携 Windows 包，以及配套的板端代理包。

产品不包含：

- 训练、验证、测试划分，以及标注。
- 把 KV260 推理结果写成真值。推理若要挂接，必须另有已经核对过的帧身份，再以独立 sidecar 进入，不能写进源视频。
- 传感器曝光时刻、传感器帧序号、真实传感器丢帧数。容器 PTS 只代表封装时间。
- 录制过程中的同步画面。
- 两台电脑同时控制同一摄像头。

## 3. 一次采集

操作员在界面顶部填写数据目录、采集人、场景备注和采集时长，然后只走一条路径。时长可选 60 秒短检、10 分钟关口或手动停止。短检和 10 分钟关口到时自动停止、校验并打开四关；手动停止仍由操作员点停止。10 分钟关口在原生预检取流低于 28 fps 时直接取消，不开始长录。

1. 确认摄像头物理连接在电脑或 KV260 上，不能两边同时占用。
2. 刷新并选中设备。KV260 默认按相机序号 `HHW001` 选择 USB 主图像节点，避开元数据节点；拔插后的 `/dev/videoN` 允许变化。
3. 设定分辨率、帧率和格式，先预览。预览不写入数据集。
4. 开始采集。写文件的进程在接相机的那台主机上运行，不依赖桌面轮询。KV260 断线后板端录制继续。
5. 用“停止并校验”或“停止并取回”结束。禁止直接关程序代替停止。
6. 查看会话状态。只有第 7 节的可入库条件全部满足，会话才能进入训练集。

界面分为四页：电脑采集、KV260 采集、会话与校验、工具设置。FFmpeg 与 FFprobe 路径只在替换内置工具时修改。连接令牌只留在本次进程内存，不写入 `capture_settings.json`。

## 4. 两种模式

| 项目 | 电脑直连 `pc_usb` | KV260 直连 `kv260_usb` |
| --- | --- | --- |
| 摄像头位置 | Windows | KV260 USB 主机口 |
| 写文件位置 | 电脑数据目录 | 板端目录，停止后按 SHA-256 取回 |
| 设备发现 | DirectShow 视频设备名 | `/dev/videoN`，并带 sysfs 身份 |
| 预览 | 单帧快照 | 录制前连续预览；开始采集先释放预览 |
| 源格式 | 由驱动协商；默认不单独选择 | `mjpeg` 或 `raw` |
| 保存编码 | 默认 `ffv1`；可选 `copy`、`mjpeg` | `mjpeg` 必须 `copy`；`raw` 必须板端 H.264 |
| 默认界面参数 | 1920×1080、30 fps、FFV1 | 打开时 1920×1080；自动连接后把已支持相机设为 MJPEG 640×480、请求 30 fps |
| 有损情况 | `ffv1` 不再次压缩已解码帧，但不能还原相机内部压缩；`mjpeg` 会再编码 | `copy` 原样封装 JPEG；`raw` 的 H.264 是有损数据 |

请求帧率是协商目标。界面和会话里出现的实测帧率必须来自计数，不能用请求值填空。

分段时长在契约中默认 300 秒，范围 10–3600 秒，当前界面不暴露。验收长录另行指定 60 秒分段，不改变默认值。

### 4.1 HHW001 原生路径

相机序号 `HHW001`、VID/PID `1c45:6200`、MJPEG、640×480、请求 30 fps 时，录制和预览走原生 V4L2，不走通用 GStreamer 源。其他相机、分辨率或格式仍走原有路径，并且不能借用这条路径的验收结论。

原生录制顺序：设置格式与帧率、4 个 mmap 缓冲、开始取流，然后在同一文件描述符上设置曝光，预热 2 秒后再交付 JPEG。MKV 直接保存这些 JPEG。PTS 来自 V4L2 时间戳并减首帧为零点。不生成固定帧率 PTS，不补帧。录制队列满时阻塞，不丢帧。预览队列只保留最新帧，允许丢弃旧画面。

停止时必须恢复进入会话前的曝光等控制并读回。异常退出或恢复失败，会话为失败。掉电或强制结束不能保证控制已恢复，操作员应再次检查相机。

## 5. 会话契约

schema 为 `capture_studio_session_v1`。会话 ID 形如 `YYYYMMDDTHHMMSSZ_` 加 8 位十六进制。

```text
captures/<session_id>/
  session.json
  capture.log
  segments/part_00000.mkv
  frames.jsonl            校验后生成
  native_capture.json     仅原生路径
```

`session.json` 记录模式、状态、UTC 时间、采集参数、分段相对路径、字节数和 SHA-256。原生路径另有摘要：完成状态、缓冲计数、全程帧率、时间戳异常计数、控制恢复是否核对通过。

`frames.jsonl` 每行是录制文件中的一帧：

- `recorded_frame_id`：从 0 起的录制帧编号。
- `segment`：所属分段。
- `container_pts_s`：封装 PTS，单位秒。
- `timestamp_source`：固定为 `recorded_container_pts`。

校验在核对 SHA-256 和文件大小之后，用 FFprobe 解码清单。分辨率必须与请求一致。PTS 缺失、PTS 不递增，或相邻 PTS 间隔大于 `1.5 / 请求帧率`，都不能当成传感器丢帧数；后一项只是容器间隔启发式。

原生逐帧诊断报告只保留前 32768 条。超过约 18 分钟后，报告仍有总计数，但不能代替对 MKV 的全量解码审计。

## 6. 当前状态字

实现里的状态迁移是：

`starting` → `recording` → `recorded` 或 `failed` → `audited` 或 `needs_review`

`recorded` 表示进程正常结束、至少有一个非空分段，且原生路径的完成状态与控制恢复都通过。`failed` 表示进程失败、没有媒体，或原生恢复未核对。

`audited` 只表示：有帧、无缺失 PTS、PTS 单调、没有超过启发式阈值的间隔、分辨率一致。`needs_review` 表示上述任一项不满足。

`audited` 不是可入库。它不检查亮度、细节、唯一图像，也不证明达到 30 fps。

## 7. 可入库规则

这是本规格相对当前界面的产品定义。一个会话进入训练集，必须同时满足下面四关。缺任一关，会话留在待复核，可以保留作诊断，不能混入训练集或独立部署验证集。

| 关口 | 通过条件 | 当前基线 |
| --- | --- | --- |
| 完整性 | 分段大小与 SHA-256 一致；视频流可严格解码；分辨率与请求一致；重复 PTS 为 0；倒退 PTS 为 0 | 自动曝光长录通过，17205 帧 |
| 帧率 | 以解码后的唯一图像计数。预热不计入。全程以及预先划定的每个 60 秒窗口都 ≥ 29.9 fps。禁止补帧或按请求帧率改写 PTS | 未通过。同一会话全程 26.132 fps，窗口最低 26.117 fps |
| 画面 | 样本来自本次录制文件，而不是预览。场景可辨认，亮度和动态范围足够看清目标。近黑或近饱和画面失败 | 通过。开始前平均亮度 126.6，录像抽样 125.4–142.2 |
| 收尾 | 停止后控制读回为进入会话前的值；相机空闲；无遗留采集进程 | 通过，控制已恢复并读回 |

电脑路径和板端路径分开归档。即使同一只相机，也不能把板端会话直接并入电脑训练集后仍称作独立部署验证。

换相机、分辨率、像素格式、曝光策略或板卡后，四关全部重做。短录不能代替长录，一种配置不能代替另一种配置。

## 8. 当前放行结论

截至 2026-10-12 的自动曝光重测，产品可以采集、取回和分开显示四关。正式数据集入口不放行。

会话 `20261012T003158Z_64e56f46` 使用与预览相同的自动曝光（模式 0），开始前样帧平均亮度 126.6。约 11 分钟录像解码 17205 帧：完整性通过，画面抽样平均亮度 125.4–142.2，收尾通过。唯一图像全程 26.132 fps，60 秒窗口最低 26.117 fps，帧率关口未过。证据在 `acceptance_runs/auto_exposure_10min_20261012/`。

此前快门优先、绝对曝光 100 的 620 秒会话达到约 29.99 fps，但画面近黑，按现在的开始前检查不会被允许开录。自动曝光下的可见画面与 30 fps 仍未同时出现。

已核对的配置只有当前这块 KV260 上的 HHW001、MJPEG、640×480、请求 30 fps：

- 会话 `20261011T150129Z_c0bd85b0`：11 段，交付与解码均为 18544 帧，唯一图像 18544，最长间隔 36.189 ms，下载校验通过。录制使用快门优先、绝对曝光 100。该曝光在当前室内场景的样图平均灰度约 1.3–1.6/255，画面近黑。完整性与帧率关口通过，画面关口失败。
- 实时预览已改为自动曝光。30 秒复测样图平均亮度约 107/255，场景可见，取流约 10.3–10.7 fps。画面可见与 30 fps 没有同时出现。
- 此前 75 秒、界面约 30 fps 的预览验收发生在固定曝光的近黑画面上。它说明传输和刷新能力，不能当作画面关口或录制关口。

电脑直连在更早的测试中出现过 20 秒 600 帧和 60 秒 1800 帧、约 30 fps 的完整解码结果。那些样图偏暗，场景也与板端不同，不能当作已经完成的跨主机对照。

便携包在本机换目录、去掉开发环境 PATH 后能启动。没有第二台电脑的相机、密钥和短录验收。

## 9. 板端服务

代理默认只监听 `127.0.0.1:8765`。桌面经 SSH 隧道访问。令牌文件权限为仅所有者可读，长度至少 32 字符，请求使用 `Authorization: Bearer`。访问日志不记录该头。

可信实验局域网里可以把监听地址改成板端地址。该 HTTP 不加密，令牌随请求传输，服务不得暴露到公网。

主要接口：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/status` `/devices` `/sessions` | 活动状态、相机、会话列表 |
| POST | `/start` `/stop` | 开始、停止并写清单 |
| POST | `/snapshot` | 单帧 PNG |
| POST | `/live/start` `/live/stop` | 连续预览开关 |
| GET | `/live/stream` `/live/metrics` | 持续 PNG 与实测帧率 |
| GET | `/sessions/{id}/files/{path}` | 按清单下载 |

预览 PNG 为 320×240。板端预览上限是 `min(请求帧率, 30)`。界面同时显示取流帧率、板端输出帧率和界面刷新帧率，统计窗口为最近数秒。断流或出错时停止预览并释放相机。

首次安装板端包需要 Python 3.10+、GStreamer 1.x 及其 Python 绑定。原生路径还要在板端用 GCC 编译 `native_capture`。`raw` 模式需要可用的 H.264 编码器。插件以板上 `gst-inspect-1.0` 为准。

## 10. 部署规格

Windows 包是完整目录或 `CaptureStudio_windows_x64.zip`，含解释器、FFmpeg、FFprobe 和依赖 DLL。只复制 EXE 不算安装。数据目录默认在程序旁的 `captures`，换电脑后重新选择。包内不含私钥、令牌、个人配置和已采集数据。

KV260 入口是 `连接开发板.cmd`。可编辑 IP、SSH 用户、私钥、板端目录和相机序号。缺少私钥时打开连接设置。程序不跳过主机指纹校验，也不发现未知 IP。私钥有口令时需事先载入 ssh-agent。新电脑需要 OpenSSH 客户端，并先手动接受一次主机指纹。

源码运行需要 Python 3.10+ 与 Tkinter。桌面界面目前只面向 Windows。

## 11. 下一版规格

按关闭顺序实施。前一项未关闭，不把后面的能力宣传成数据集能力。

### P0：打通可入库

1. 已完成：四关分开写入会话并在界面显示。`audited` 仍只表示容器时间戳启发式结果。
2. 已完成：KV260 原生路径的预览和录制使用同一曝光，并写入 `session.options`。样帧过暗、过亮或细节不足时不能开始。
3. 已重测，未通过：自动曝光长录的画面、完整性和收尾通过，唯一图像帧率 26.132 fps。在同时满足画面和 29.9 fps 之前，正式数据集入口不放行。
4. 仍待做：增益、相机序号和 USB 速度写入每个会话。停止后控制恢复失败时，界面要求人工复查相机。

### P1：把采集口径收进产品

5. 已写入会话并可在设置页保留：镜头、光照、距离。目标尺度和遮挡仍待做。自由文本备注保留。
6. 录制结束后显示实测唯一帧率，与请求帧率并列。
7. 界面可改分段时长；未改时仍是 300 秒。
8. 用同一相机、同一场景、同一曝光完成电脑与 KV260 的短录和长录对照，两套会话分开编号。
9. 在第二台 Windows 电脑上完成解压、SSH、短录、停止、取回、校验。

### P2：采集之后的能力

10. 若做录制中画面，预览必须继续只丢自己的队列，录制队列保持阻塞不丢帧，并在界面标明二者不同。
11. 推理 sidecar 仅在帧身份已经核对后导入。
12. 按会话或场景划分训练、验证、测试。划分属于数据集工具，不属于本次采集写盘路径。
